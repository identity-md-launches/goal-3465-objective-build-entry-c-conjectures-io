# m0-exp-layout: contiguous bank for the Thumb exp high words (negative result)

Source `entry.c` SHA-256 `b5daaa84e90e59f98fc4e0da4263bf67ad82b7002949e6bce7fa5781ac643cee`;
id50 base SHA-256 `88617bb49e36a06cabd7d84ce6fe504ee337f8f41ad7c55bc72f696db94060c3`.
Exact diff: [diff-vs-id50.patch](diff-vs-id50.patch) (generated by [tools/make_candidate.py](tools/make_candidate.py)).
Status: **measured, regression**. Not an eligible optimisation; the code generation differs from id50 (normalised hash differs), it is not a duplicate.

## Change
The 512 high words are `t_eps[0..511].t_aux`, stride 16 bytes. They are copied value for value into
`static const uint32_t t_hb[512]`. Seven loads now read `t_hb[idx]`:
`t_mt` (`kp & 511`), `t_mn` (`n >> 23`), `t_exp_res` (`m`), `t_exp_den` (`kb & 511`) and the two table loads
in `t_eik_exp` (`kb >> 23`). `t_eps` itself is untouched, so every other reader keeps its data.

## Why every result is identical
Each old address was `&t_eps[0].t_aux + 16*idx` and now is `t_hb[idx]`, the same word.
- `t_mt`: `(kp<<23)>>19 = 16*(kp&511)`; `t_mn`: `(n>>19) = 16*(n>>23)` with `n = kp<<23`; `t_exp_res`: `m<<4`; `t_exp_den`: `(kb&511)<<4`.
- `t_eik_exp` loads `*(t_tb + (kb>>19))` with `kb` rotated right by 9. `kb>>19` is `16*(kb>>23)` plus a constant in the low bits:
  `t_xrow` (tb = aux): the 17-bit value is rotated by `rB&31 = rB2&31 = 9` for all 12 rows, so bits 19..22 are 0 (offset +0).
  `t_xkm` (tb = &t_v = aux-8): `k3 = 0x8000fbff`, bits 28..31 = 8, rotated to offset +8, so aux-8+8 reaches the row aux. `t_xkq` (tb = aux-2): `k3 = 0x2000fc00`, bits 28..31 = 2, offset +2, reaches aux. No borrow or carry reaches bit 28 (kfn < 2^16). So all three read row `kb>>23` aux, which is `t_hb[kb>>23]`.
- The old `t_tb` pointers stay assigned but are no longer read on live paths. Aliases through `t_eps[w&255]` casts to `t_xr`/`t_xks`
  (only reached when `w*w` is 13/29/53/61/77/21 or `w*(w>>1)` is 37 mod 2^32 for negative NaN/inf words) are dead:
  scanned all 0xFF800000..0xFFFFFFFF, zero hits ([tools/dead_branch_scan.py](tools/dead_branch_scan.py); squares of odd numbers are 1 mod 8). Their `t_eps` data is unchanged anyway.
- Fast returns, special cases, `t_eps` rows, slow paths and the selector `EIK_SEL` are unchanged; no probes added.

## Thumb code generation
`asm/thumbv6m-touched-functions.txt`: `t_exp_res` 84 -> 83 static instructions, `t_exp_den` 86 -> 85 (one fewer, same load count 13/11 and shifts);
whole-file `ldr` 226 -> 235 (ldr with register offset 14 -> 18), literal-pool entries for `t_hb` appear in 5 functions. So the load sequence did not get cheaper:
the bank base is another literal-pool word (`.long t_hb`) that the old code got for free from the `t_tb` field/row pointer, and the added
whole-function differences in `t_eik_exp` (the exp typical mean rises ~4.8 instructions) are register-allocation/inlining side effects, not anything this experiment targeted.
Because `t_eps` must stay for the other aliases (sigmoid/tanh row pointers, `t_dkn`, `t_m1t`, `t_srow`), the bank is a pure 2048-byte duplicate.
